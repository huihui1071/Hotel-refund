# 运营指标与 Badcase 闭环

## 北极星指标

**正确退款任务闭环率** = 在结果、金额、权限和流程均正确的前提下，完成取消、退款或明确替代方案，并得到系统终态或用户确认的有效案件数 ÷ 有效退款案件数。

它约束 Agent 不能用“已经回复”“已发起”或“未转人工”冒充真实解决。

## 指标体系

| 维度 | 指标 | 关键口径 |
| --- | --- | --- |
| 业务结果 | 正确解决率 | 抽检结果与政策、事实、权限一致 |
| 业务结果 | 实际到账闭环率 | 必须有支付终态或用户确认 |
| 效率 | 首次有效决定时间 | 从进线到可执行方案或明确缺失项 |
| 效率 | 最终到账时间 | 从首次退款申请到资金到账 |
| 自动化 | 自动完成率 | 无人工介入且业务状态真实完成 |
| 体验 | 一次解决率 | 观察窗内同订单、同问题无重复进线 |
| 体验 | 用户操作次数 | 补资料次数与跨渠道联系次数 |
| 协作 | 供应商首次响应/SLA 达成率 | 按供应商和场景拆分 |
| 质量 | 人工改判率 | 人工改变 Agent 结论或金额 |
| 风险 | 承诺失真率 | 对话声称完成但系统或外部结果不支持 |
| 风险 | 错误退款/重复赔付率 | 资金损失类硬指标 |
| 风险 | 该转人工未转率 | 高风险召回优先于自动化率 |

## 处理链路漏斗

运营看板按同一有效案件分母观察：

```text
有效退款案件
→ 成功关联订单
→ 形成首次有效决定
→ 用户确认或系统可执行
→ 业务状态完成
→ 到账或结果确认
→ 正确退款任务闭环
```

每层同时记录案件数、总体转化率、环节流失量和原因标签。结果指标判断“是否解决”，过程指标解释“为什么没有解决”，风险指标约束“不能为了自动化而错误处理”。

## Badcase 生命周期

```text
发现 → 归因 → 修复 → 回归验证 → 上线观察 → 关闭
```

| 阶段 | 产物 |
| --- | --- |
| 发现 | Case/Trace、用户影响、风险等级和场景标签 |
| 归因 | 问题归属到数据、规则、Prompt、Tool、权限、外部接口或交互 |
| 修复 | Owner、方案、SLA 和受影响用例 |
| 回归验证 | 新增失败样本并通过自动化或人工评测 |
| 上线观察 | 观察同类错误率、核心指标副作用和复发情况 |
| 关闭 | 修复上线、回归通过且观察窗内未复发 |

## 运营原则

- 每个 Badcase 必须能回到具体场景、Workflow 节点、Tool 回执和规则版本；
- 高风险问题按资金损失、错误承诺和该转未转优先处理；
- 人工改判必须沉淀原因，不能只覆盖 Agent 输出；
- 修复需要进入 Eval，避免相同问题只在单个案件中被人工兜底；
- 看板中的数值均为演示用 Mock，只验证指标结构和诊断逻辑，不代表真实业务表现。
