# Design System

## Direction

设计系统采用“克制的任务型界面”：以 shadcn/ui 作为可访问组件基础，以 coss 的中性、紧凑和完整状态语言作为视觉参考。界面不复制去哪儿、Cal.com 或任何开源项目的品牌外观。

默认浅色。面试官会在桌面端快速浏览，真实 C 端用户可能在酒店前台、路途中或明亮环境下使用手机；浅色能提供更直接的状态辨识和文本可读性。

## Color Strategy

使用 Restrained 策略。带冷蓝倾向的中性色占主要表面，蓝色只用于主操作、当前选中和信息状态，不超过约 10%。成功、等待、风险和错误使用低色度语义色，并始终附带文字或图标。

```css
:root {
  --background: oklch(0.985 0.004 250);
  --surface: oklch(0.998 0.002 250);
  --surface-subtle: oklch(0.968 0.006 250);
  --foreground: oklch(0.225 0.018 250);
  --muted-foreground: oklch(0.505 0.018 250);
  --border: oklch(0.905 0.009 250);
  --primary: oklch(0.525 0.165 252);
  --primary-hover: oklch(0.47 0.16 252);
  --primary-foreground: oklch(0.985 0.004 250);
  --success: oklch(0.57 0.125 155);
  --success-surface: oklch(0.96 0.035 155);
  --warning: oklch(0.65 0.135 72);
  --warning-surface: oklch(0.965 0.045 82);
  --danger: oklch(0.58 0.185 28);
  --danger-surface: oklch(0.965 0.035 28);
  --info-surface: oklch(0.955 0.025 250);
  --focus: oklch(0.65 0.15 252);
}
```

禁止使用纯黑、纯白、大面积高饱和蓝、渐变文字、紫色 AI 渐变和玻璃拟态。

## Typography

- 字体：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
- 金额和时点使用 `font-variant-numeric: tabular-nums`。
- 页面标题：28/34，600；移动端 24/30。
- 区块标题：18/26，600。
- 核心结论：20/28，600。
- 正文：14/22，400。
- 标签与辅助信息：12/18，500。
- 正文最大行宽 70ch；用户任务区域最大宽度 680px。

不在按钮、标签或数据区使用展示字体。

## Radius, Border and Elevation

- 基础圆角 8px；主任务区 12px；胶囊仅用于状态标签。
- 常规分组使用 1px 边框或背景差，不为每段内容创建卡片。
- 浮层使用 `0 12px 32px oklch(0.22 0.02 250 / 0.10)`。
- 页面主体不使用悬浮卡片墙；只在订单选择、可执行方案和需要独立语义的状态块使用容器。

## Spacing and Grid

- 基础单位 4px。
- 控件内部：8、12、16px。
- 相关内容间距：8 或 12px。
- 区块间距：24 或 32px。
- 页面章节：48 或 64px。
- 桌面最大宽度 1440px，左右页边距 32px。
- 场景模拟桌面布局：240px 场景栏 + minmax(520px, 1fr) 用户任务区 + 360px Trace。
- 小于 1100px：Trace 变为右侧抽屉。
- 小于 768px：场景栏变为顶部选择器，只显示 C 端任务区，主操作固定在底部安全区。

## App Shell

全局只保留三个一级导航：`Agent 设计`、`场景模拟`、`运营看板`。使用顶部栏，不使用后台式永久侧边栏。

顶部栏包括：

- 左侧：`酒店退款 Agent`；
- 中部：三个一级导航；
- 右侧：始终可见的 `Mock 数据` 标识；
- 不放头像、通知、设置、搜索和技术 Logo 墙。

## Component Decisions

### Button

- 主按钮高度：桌面 36px，移动端 44px。
- 每页最多一个实心主按钮。
- 主按钮只用于推进当前任务；描述完整动作，例如“确认取消并申请退款”。
- 次操作使用 outline；解释和查看详情使用 ghost 或文本按钮。
- 必须实现 default、hover、focus-visible、active、disabled、loading、error。

### Status Label

- 使用图标 + 文本 + 低色度背景。
- `已完成` 为绿色，`等待外部` 为琥珀色，`需要用户` 为蓝色，`已阻断` 为红色。
- 风险等级不向普通 C 端用户展示；仅在演示 Trace 中显示 L0–L4。

### Solution Panel

C 端不展示系统如何思考和处理，只展示用户做决定所需的信息。方案卡固定包含：

1. 一句话结论；
2. 推荐的可执行方案；
3. 退款金额、扣费或当前状态；
4. 方案对订单的直接影响；
5. 必须提前说明的风险或不可逆后果；
6. 当前唯一主操作。

用户提交后，方案卡切换为可验证的处理结果、下一步安排和明确更新时间。不得在 C 端出现责任链、内部状态机、Tool、规则命中、证据明细、风险等级或审计术语；这些信息仅属于面试演示 Trace 和运营后台。

不得使用虚假百分比进度条，也不得用“处理中”代替明确结果或更新时间。

### Confirmation Surface

不可逆操作使用独立页面或内联确认区，不默认使用模态框。内容顺序：订单对象、退款金额、扣费、退款路径、不可逆后果、确认按钮。

### Workflow Trace

Trace 是面试演示层，不是开发控制台：

- 每步只显示节点、执行者、已确认事实、命中规则、Tool 结果和状态迁移；
- 不显示 Chain of Thought、完整 JSON、Prompt 或密钥；
- 当前步骤使用蓝色 2px focus ring，不使用彩色侧边条；
- Tool 输入和输出按需展开。

### Data Table

- 运营看板的场景表现使用表格，不使用十二张指标卡。
- 表头 12px，正文 13px，行高 44px。
- 金额、比例和时长右对齐并使用 tabular numbers。
- 风险或异常行使用低色度行背景及文字说明。

## Page-Specific Hierarchy

### Agent 设计

页面目的：60 秒内让面试官理解系统如何工作。

1. 一句话系统边界；
2. 主流程图；
3. 三条业务出口；
4. Tool 读取与写入权限门；
5. 唯一主操作“开始场景模拟”。

### 场景模拟

页面目的：验证某一场景的端到端决策和业务推进。

1. 场景选择；
2. C 端当前任务；
3. 当前结论和唯一动作；
4. 预期管理面板；
5. 演示模式 Trace。

十二个场景不做十二个等宽 Tab，按四组组织：

- 取消与变更：A、B、F、I；
- 退款与支付：C、J；
- 履约与住宿：D、E、H；
- 特殊审核：G、K、L。

### 运营看板

页面目的：定位退款任务在哪个环节流失、风险是否可控，以及 Badcase 是否完成修复闭环。

1. 全局筛选与模拟数据声明；
2. 北极星指标“正确退款任务闭环率”、口径和健康结论；
3. 从有效退款案件到正确闭环的处理链路漏斗；
4. 业务结果、效率、自动化、体验、协作、质量和风险指标矩阵；
5. Badcase 发现、归因、修复、回归、观察、关闭流程；
6. Badcase 队列及选中问题的闭环详情。

北极星承担总结果判断，核心指标承担定位，漏斗承担过程诊断，Badcase 工作台承担改进执行。不得用多个等大 KPI 卡片平铺，也不把 Token 成本等技术指标提升到业务指标之前。

### Metric Ledger

- 指标按业务语义分组，不按视觉均分成卡片；
- 每行必须包含当前值、目标或基线、环比、状态和口径入口；
- 风险指标采用“越低越好”的方向，环比下降显示为改善；
- 所有比率明确分母，时间指标明确起止事件和 P50/P90；
- 模拟数据必须持续显示，不因筛选或滚动消失。

### Funnel

- 漏斗使用绝对案件数、相对总量转化率和环节流失数；
- 不使用夸张面积梯形误导比例，采用同一宽度基线的水平条；
- 环节依次为：有效退款案件、首次有效决定、方案确认或明确替代方案、业务状态完成、到账或结果确认、正确闭环；
- 点击流失环节后过滤下方指标和 Badcase 队列。

### Badcase Workspace

- 顶部显示 Badcase 闭环率、逾期数和复发率；
- 队列表格包含问题类型、影响案件、风险、当前阶段、Owner、SLA；
- 选中一行后展示事实证据、根因、修复动作、回归用例、上线观察和关闭标准；
- “已回复”“已建工单”不算闭环，只有修复上线、回归通过且观察窗无复发才能关闭。

## Motion

- 控件反馈 150ms，面板切换 200ms，使用 ease-out-quart。
- Trace 新步骤只做透明度和 `transform: translateY(4px)` 进入。
- 禁止页面入场编排、弹跳、脉冲 AI 动效和布局属性动画。
- `prefers-reduced-motion` 时关闭所有非必要过渡。

## Accessibility

- WCAG 2.2 AA。
- 所有按钮和选择器支持键盘，焦点环宽 2px。
- 移动端触控目标至少 44×44px。
- 状态不能只依赖颜色。
- 动态结果使用合适的 `aria-live`，但避免每个 Trace 步骤都打断读屏。
- 时间写出日期和时区语义，避免只写“稍后”或“很快”。
