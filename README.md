# 去哪儿酒店退款智能客服

这是“去哪儿酒店退款业务智能客服”的产品研究与方案工作区。首版确定由 Agent 代表模拟的去哪儿酒店售后团队，直接服务 C 端用户；所有无法取得的内部订单、政策、接口和指标均使用明确标注的 Mock，不包装成真实业务信息。

## 在线演示

- GitHub Pages：[https://huihui1071.github.io/Hotel-refund/](https://huihui1071.github.io/Hotel-refund/)
- GitHub 仓库：[https://github.com/huihui1071/Hotel-refund](https://github.com/huihui1071/Hotel-refund)

在线版本使用浏览器端确定性 Mock Adapter；本地版本可连接 FastAPI，实际执行 SQLite、规则引擎、Tool 权限网关和 A–L Workflow。两种模式共用相同的前端响应结构，且均明确标注为 Mock。

## 当前阶段结论

1. 场景库覆盖 A–L，但自动化深度分层：低风险场景自动闭环，协同场景建单并跟踪，跨境和团体订单进入专席。
2. “不可取消”订单不能只返回一句规则；Agent 至少要检查条款快照、提示证据、取消提前量、供应商可协商性和例外证明，再决定自动处理或转人工。
3. 自动解决必须以订单、退款、变更、住宿恢复或工单状态真实推进为准，不能以“用户未转人工”或“机器人已经回复”为准。
4. 当前已完成产品与技术规格、A–L Mock 数据、Tool 契约、可执行 Mock 后端、自然语言适配层和三模块 React 前端。

## 已确认的产品决策

- Agent 代表模拟的去哪儿酒店售后团队，直接面向 C 端用户。
- 项目用于面试后的求职作品展示，首要目标是在 3–5 分钟内体现需求分析、产品设计、Agent 设计和风险评测能力。
- 无法获得的内部订单、政策、接口和指标均使用明确标注的 Mock，不包装成真实业务信息。

## 快速运行

启动后端：

```bash
cd backend
UV_CACHE_DIR=/tmp/qunar-uv-cache uv sync --extra dev
.venv/bin/python -m app.cli init-db --reset
.venv/bin/uvicorn app.main:app --reload --port 8000
```

启动前端：

```bash
cd frontend
npm install
npm run dev
```
